# Termeta 官方服务与接入边界

更新：2026-10-20。官方服务为可选独立项目，不替代桌面 IPC、会话 actor 或本机保险库，本地功能无需账号。本文只维护客户端与独立项目的边界；部署细节由各项目维护。

## 当前范围

| 项目 | 职责与文档 |
| --- | --- |
| 服务端 | Python/FastAPI/Tortoise ORM、外部 MySQL；账号、密文备份/同步、分发/updater 与管理员 API |
| 用户端 | 邮箱及 GitHub/Google 网页登录、基础账号管理和显式桌面授权 |
| 管理端 | 管理员登录及软件版本草稿/发布/撤回/删除；后端逐请求校验管理员权限 |

客户端已有浏览器登录和官方同步源码，尚未接入 Tauri updater 插件。完整服务部署、MySQL/OAuth 联调、跨设备与三平台验收仍待完成；其他仓库的基础代码不能视为客户端验收证据。

2026-10-19 决策：账号、密文同步与更新控制面独立部署，终端和本地数据仍由客户端 Rust 管理；用户端/管理端不接入桌面 IPC，不接收保险库密码或业务明文。

## 账号、备份与同步

桌面通过 termeta.io/GitHub/Google 浏览器登录，桌面会话永久可撤销；网页和管理会话有限期。提供方秘密留在服务端，应用 Token 留在 Rust/SQLCipher；相同邮箱不自动合并身份。完整 proof、回跳、owner 和撤销边界见 [账号认证](25-account-authentication.md)，HTTP DTO 以 服务端认证契约 为准。

官方模式使用 `/api/sync/vault` 单头密文、revision CAS 和客户端稳定 ID 三方合并。云包使用本地主密钥/派生盐，服务端无法验证保险库密码；门禁、改密和故障恢复见 [官方同步](26-official-vault-sync.md)。退出保留本地数据。

Gist/WebDAV 仅在本地模式使用独立备份密码，不共用官方配置。历史 `/api/backups` 不可变版本不会自动转成同步头或重加密，仍受原包密码保护，见 服务端备份契约。

用户端/管理端采用固定 HTTPS 来源和同源 `/api/`，SPA 路由不能吞掉 API/OAuth 回调。Cloudflare 与 Tunnel 路由、缓存和部署步骤见 用户端部署 及 管理端部署，不在客户端文档复制实时基础设施配置。

## 分发与更新

服务端遵循 Tauri 动态更新协议，无更新返回 204，有更新返回签名及 HTTPS 制品信息。签名私钥仅在发布环境；客户端接入时必须内置公钥验证，不能绕过签名。管理员显式发布/撤回，目前仅稳定渠道。

制品上传、签名/公证、CDN 和发布流程尚待落实，见 服务端分发契约。服务端有更新接口不等于桌面已具备自动更新。

## 远程协助（仅规划）

拟采用独立中继和出站隧道，由用户显式共享、一次认领并可撤销；默认只读，控制另行授权，不暴露任意本地端口或原主机凭据，不自动广播远程输入。gateway、会话路由和客户端共享尚未实现，设计及验收边界见 远程协助方案。
