# 验证、兼容性与性能计划

日期：2026-10-15。**以下均为后续授权后执行的方案，本轮未运行。** 不因为文档要求“必测”而擅自构建、启动测试服务器、连接真实主机或开启 CI。

## 1. 执行原则与证据

源码/文档变更允许做无构建静态检查；Rust 测试、cargo check/clippy、前端 build、Vite/Tauri 启动、Playwright UI 都可能构建/运行，必须遵守 AGENTS.md。不要主动加入会在 push 时自动编译的工作流来绕过约束。

验证证据至少记录：日期、提交/工作树状态、平台/架构、工具链、依赖锁版本、服务端版本/配置、命令或手工步骤、预期/实际、耗时/资源测量方法、失败与限制。秘密、私钥和终端敏感内容不得成为 fixtures 或报告附件。

可以提前设计和编写有意义的测试用例，但执行需要授权；不要为纯文案/文档变更写镜像实现的测试。当前阶段以可审阅的验证规格为交付。

## 4. 关键反例与竞态

必须专门验证：open Promise 尚未返回就收到 event；同 requestId 重试；close 与信任回复同时发生；认证提示超时后迟到回复；输出队列满同时远端退出；ended 早于尾数据到达；重复/越界/跨会话 ACK；write 部分成功后连接断开；PTY 请求已发送却被拒绝；窗口重载/销毁；持续 stderr/extended data；库内部队列已满时 KeepAlive 是否仍可驱动。

fake driver 可注入延迟、丢 ACK、错误与乱序状态；IPC 帧本身不接受乱序修补。测试应验证业务不变量，如“终态后无资源”“未信任不提交秘密”“未消费字节不释放信用”，避免仅对照枚举逐行复制实现。

SP-07（未执行）：选择同一 Reka/xterm 稳定 release 组合，验证对话框焦点与终端 IME、Tabs/Presence 的宿主保活、Portal/CSP、CSS 自定义主题；同时验证旧流解析栅栏、未闭合控制序列与 UTF-8、旧全屏快照与输入模式重置，在不清空/重建原 xterm 的前提下完成重连。Tree Alpha/Splitter 按启用阶段单独验证。若不能满足终端保留要求，调整适配器/控件集成，不能降级需求。

SP-08（M2，未执行）：按三平台键盘布局、IME/AltGr、终端/主机/文件/设置焦点、弹窗与原生菜单测试路由；改绑远端控制键必须提示且只执行一次；录制不发送，导入冲突不自动生效，断线历史链接/复制可用。系统后台插件另在 M5 验证，不是 M2 keymap 的前置依赖。

SP-09（M2，未执行）：固定 xterm release 核对 palette/扩展色字段，验证独立预览、自选颜色、全局/profile/临时覆盖、热应用不清历史、隐藏终端更新、内置只读副本、导入/导出往返/恶意输入/重名/引用删除。显式 truecolor 与 ANSI 的边界须在 UI/测试说明一致。

SP-10（M3，未执行）：受控两台服务器及授权本地根，覆盖独立 subsystem、全部端点组合、远端中转大文件和目录、多任务公平性、源/目标变化、同文件/子目录保护、覆盖确认后目标变化、服务器不支持原子 replace、quota/磁盘满/取消、断线清理。检查旧目标在可保证的安全路径保持完整，弱保证明确且无默认破坏性 fallback；属性拒绝/部分失败与 UTF-8 外文件名有真实结果。目标目录创建/符号链接/替换等竞态不可只测静态 happy path。

SP-11（M3，未执行）：分别验证 Explorer、Finder、Linux X11/Wayland 文件管理器的原生拖入与拖出，特别是准备 staging 后再拖、多选/目录、OS 冲突/取消/延迟读取、磁盘限额/清理、native drop 与 Web 内部拖拽去重。失败平台保留明确限制和替代下载，不标记该需求通过。

## 6. 性能目标与测量方法

以下是初始预算，不是库保证或本轮结果。所有数据记录 CPU、内存、分辨率、字体、WebView、构建模式、终端尺寸与日志设置；debug 数值不能直接当 release 产品指标。

| 指标 | 初始目标 | 测量方法 |
| --- | --- | --- |
| 空窗口启动到可操作 | ≤2 秒 | 本地离线启动；冷/热分开，至少 20 次，报告 p50/p95 |
| 交互响应 | 低延迟测试网络下，应用新增开销 p95 ≤20 ms | 相同服务器/网络与参考终端对比，区分 RTT 与应用开销 |
| 连续输出吞吐 | 可见终端 ≥2 MiB/s，持续 60 秒 | 固定字节样本与行宽，计实际消费 ACK，不计 send 入队吞吐 |
| 多会话稳定性 | 20 会话可用；5 个持续输出其他会话可操作 | 观测按键/关闭延迟、队列水位、CPU、内存 |
| 内存 | 单可见普通会话总进程树目标 ≤200 MiB；10 普通会话目标 ≤500 MiB | 包含 WebView/GPU，固定 scrollback；平台差异需记录 |
| 内存稳定性 | 高输出 10 分钟后无持续线性增长 | 分开记录传输缓冲、终端滚屏、进程 RSS/private working set |
| 关闭与取消 | p95 ≤3 秒 | 正常、远端不响应、认证等待、满队列/无 ACK 分别测 |
| 生命周期泄漏 | 连接/关闭 100 次后无残留 session/task/socket | 连接数/任务数/内存基线与系统资源检查 |

M3 文件传输另测：4 个并发大文件（含远端中转）及大目录扫描时，传输块/队列保持 [SFTP 文档](16-sftp-workspace.md) 预算（初始单任务在途 2 MiB、全局 16 MiB，库内部另算），传输进度节流且终端输入/KeepAlive/取消仍可响应。中转文件内容不出现在本地 staging/DB/日志，只有用户明确原生拖出才允许受控 staging；不把文件大小线性增长的内存视为正常。

强制不变量比吞吐目标更优先：有界缓冲、可取消、无字节静默损失、输入不重复。暂未达性能目标时记录测量与优化依据，不通过取消信任校验、无限缓冲或丢输出“达标”。

## 7. 静态安全与数据检查

依赖安装、公告/许可证核查、格式与不触发编译/运行项目的静态检查可按任务需要主动执行；项目构建、启动、单元与集成验证仍须用户明确要求。执行前辨别命令及安装生命周期脚本是否间接触发项目构建/运行。测试秘密必须是生成的专用数据；验证保存密码后在 DB/日志/备份/导出中搜索其唯一标记，验证默认配置没有输出内容日志。测试结束清理专用 OS 凭据 item/服务器与临时文件，保留脱敏结果。
