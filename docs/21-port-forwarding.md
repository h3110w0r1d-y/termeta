# SSH 端口转发

更新：2026-10-18。本地、远程和动态 SOCKS5 已有源码；真实 SSH 三模式及平台验收尚未完成。

## 1. 模式与网络边界

规则引用已保存 SSH 主机，保存/复制不连接，应用重启不自动启动；启动不创建终端标签。

| 模式 | 监听位置 | 目标连接及 DNS 解析位置 | 示例 |
| --- | --- | --- | --- |
| 本地 | 本机 | SSH 服务器 | 本机 `127.0.0.1:15432` → 服务器侧 `db.internal:5432` |
| 远程 | SSH 服务器 | 本机 | 服务器 `127.0.0.1:8080` → 本机侧 `127.0.0.1:3000` |
| 动态 SOCKS5 | 本机回环 | SSH 服务器 | `127.0.0.1:1080`，客户端逐连接指定目标 |

监听地址须为 IP，IPv6 不带方括号，默认 `127.0.0.1`；端口为 1–65535，不自动分配。固定目标支持域名或 IP；目标回环地址指表中“目标连接位置”的机器。监听 `0.0.0.0`/`::` 可向其他设备开放，远程实际范围还受服务器 GatewayPorts 限制。

SOCKS5 无认证且仅限回环、TCP CONNECT；支持 IPv4/IPv6/ASCII 或 IDNA 域名，无 BIND、UDP、密码或 SOCKS4。域名传给 SSH direct-tcpip，不在本机解析；客户端须自行选择代理端 DNS，否则仍可能产生本机查询。代理监听本身无 TLS，进入 SSH 的流量才加密。

## 2. 连接与生命周期

每条规则独立建立 SSH，从 Rust 读取已保存主机的当前配置和凭据；复用 [主机信任与认证](05-ssh-design.md)，不借用终端、不申请 PTY/Shell/SFTP，不执行启动命令、系统识别或新增终端历史。

监听绑定或服务器接受远程监听后才 Connected；不代表每条目标流都可用。建立和运行期间可停止，编辑/删除须先停止。单条流失败只关闭该流；SSH 断开结束整条规则，不自动重连或重放。

停止取消监听和全部子任务，关闭底层 TCP；服务器随 SSH 断连释放远程监听。窗口销毁或会话对账发现未被前端持有时同样清理，不提供后台守护进程或专门睡眠恢复。删除主机将规则引用置空并保留规则，已运行的独立连接继续至停止；再次启动须重新选择主机。

## 3. 权限、配额与源码

壳使用独立 `forward_sessions`，每 manager 最多 20 活动会话、4 建立并发。规则 CRUD 与启停命令均校验 main 窗口、保险库和 owner，settings 窗口无权限；保存/删除使用 revision，秘密不复制进规则。

每规则最多 64 条并发流（含握手/建连），远程接入队列 32 项。每 SSH channel 为 256 KiB 窗口、32 KiB 最大包、16 消息缓冲；正文只在 Rust 通过有界缓冲和 SSH 背压中转，不进入 JS 或持久化。SOCKS 协商限 10 秒、direct channel 建立 30 秒、远程转发本机目标建连 15 秒，停止取消全部等待。

## 4. 验证边界

规则校验、监听端点、SOCKS 协商与存储有回归源码，不代表已运行通过。三平台绑定、真实服务器策略、信任/认证、DNS、半关闭/大流量、并发上限、停止释放及断网回收仍待验收，见 [产品需求](01-product-requirements.md#11-运行验收边界)。跳板、Agent、UDP、自动启动及自动重连尚未实现。
