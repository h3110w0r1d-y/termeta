# 双模式与官方保险库同步

更新：2026-10-20。本文描述当前源码契约，尚未完成 Rust 编译、多设备、真实服务与三平台运行验收。

## 模式与进入条件

| 状态 | 行为 |
| --- | --- |
| 首次启动 | 选择浏览器登录官方账号，或本地/离线模式 |
| 官方账号、云端空、本地全新 | 设置至少 12 字符保险库密码，创建本地库，上传加密全量业务快照 |
| 官方账号、云端空、本地已解锁 | 验证现有本地保险库密码，用现有主密钥上传 |
| 官方账号、云端有数据 | 必须先输入云端保险库密码并完整认证/校验云包；失败不进入工作台，可退出使用本地模式 |
| 已有本地库仍锁定 | 先用本地密码解锁，再验证云端密码；二者可能不同，不允许用云数据覆盖锁定库 |
| 本地转官方 | 验证云密码、对齐本机主密钥、合并两端业务数据后上传；云端空时沿用本机密码 |
| 官方退出 | 撤销本机会话，保留保险库、数据与已运行终端，切回本地模式 |

已完成密码确认的会话持久化确认标记；重启后可复用系统钥匙串自动解锁的本地主密钥。先检查本机库，再读账号，避免锁定 SQLCipher 时的空摘要误判为本地模式。新登录不能因重启跳过密码确认。已确认且有同步基线的本机在服务不可达时保留本地使用能力并显示同步错误；新设备无法验证云数据时不会绕过密码流程。

启动恢复出的账号由当前门禁检查处理，不再次触发自身检查。同一窗口的并发同步摘要读取共用请求，期间收到变更通知则在完成后重新读取；切换账号使旧摘要失效。Rust 摘要查询等待正在进行的同步完成，再判断账号和门禁状态，不把操作锁占用当作退出登录。尚未确定门禁时显示进度，需要密码时才显示密码说明和表单；后续状态就绪会重新检查进入条件，初始化期间发生的账号切换或密码门禁变化不能被迟到结果放行。

门禁隐藏并禁用已挂载工作台的交互，保留稳定终端宿主，不因登录/同步或模式切换销毁终端。密码错误限制属于桌面界面边界，服务器只保存密文，无法判断用户输入密码是否正确；本轮没有实现忘记密码后的云端清空功能。

## 密钥与数据范围

官方同步直接使用本地保险库的 Argon2id 主密钥，包里的派生盐与本地 vault 元数据一致，AES-GCM 每次使用新随机 nonce；沿用 [TMETABK1 封装](22-data-backup.md#3-包格式与密码)。不另存官方备份密码，不上传密码或主密钥。新设备从包盐和输入密码派生相同密钥，完整认证并校验快照后创建本地库。已有本地库在解锁后通过既有可恢复的改密文件切换对齐云主密钥，UUID 和本地数据保留。

全量是白名单业务快照：主机/分组/凭据、认证关联、标签/收藏、保存工作区、转发规则、主机信任与 Snippets。应用设置、快捷键/配色、会话日志、运行终端、设备授权路径、官方 Token 和第三方秘密只保留本机，不同步。详见 [数据范围](22-data-backup.md#1-范围与操作语义)。

Gist/WebDAV 使用独立备份密码，只在已解锁的本地模式设置中提供；Rust 同时验证模式。官方模式隐藏并拒绝第三方备份命令，保留已保存的第三方配置供退出后继续使用。

## 合并与并发

服务端 `/api/sync/vault` 每账号仅维护当前密文头和递增 revision，GET 读取，PUT 必须携带读取时的 base_revision。409 表示另一个设备先写入，客户端重新读、合并并有限重试，不能无条件覆盖。请求失败可能已提交，下一次先读头；不盲目重放同一 PUT。

本机 SQLCipher 的独立同步表保存账号/来源隔离的已观测云端快照，既不进入业务快照也不经过前端。首次关联按稳定 ID 合并两端，后续用已观测基线做三方比较：单边增删改采用变化，双端相同变化去重，删除与修改并发保留修改；同一实体并发修改采用本地完整版本。SSH 配置、认证和专属凭据作为一个整体选择，避免拼成不可用认证链。同名标签归一引用，主机名称冲突用稳定后缀保留两项，重复同步不生成新 ID。

已吸收的云快照基线与本地合并在同一事务保存，上传冲突、丢响应或退出后不会把下载副本误判为本地修改；本地乐观锁计数不参与业务变化判断。引用闭包、防环与结构校验在事务内保证，未涉及的本机设置、会话日志与本地配置保留。已有主机信任与云端的同端点公钥冲突时拒绝合并，要求用户核实，不静默更新或增加另一把 pin。无法解消的业务关联冲突回滚，不发布不完整快照。内容无变化时不改业务表、不上传新版本。

账号密码确认后执行首次同步，官方模式后台定期合并并上传当前全量快照，也可手动重试；当前为整包同步，无逐字段实时推送、历史版本 UI 或逐项冲突编辑器。网络失败保留本地数据并显示错误，随后自动重试；检测到云端主密钥变化则暂停并回到云密码门禁。同步读取的业务事务与网络等待分开，专用同步操作锁不阻塞会话 actor。

## 改密与恢复

本地模式改密只改变本机库，不影响既有第三方备份密码或旧包。官方模式先验证旧本地密码、同步最新云端，再用新盐和新主密钥加密全量业务数据，以 CAS 提交云端，成功后执行本地可恢复重加密。其他设备检测新盐后要求输入新云密码。

云端和本地文件不是跨系统原子事务：CAS 未确认时不改本机密码，网络中断可能意味着云端已采用新密码；云端成功但本地切换失败时，保留旧库与恢复材料，回主窗口用新云密码继续对齐。改密关键任务独立于窗口等待者完成，不能因关闭设置或 IPC 取消中断文件切换。进程强制退出仍依赖原有 password-change 恢复流程。

官方当前头替换后不保留旧主密钥版本；服务端历史 `/api/backups` 独立版本不自动转换或重加密，仍需要原包密码。本机物理副本、未清理的改密恢复副本与系统快照仍由各自旧密码保护。

## 模块与验收

`official_sync` 壳模块负责编排、HTTP 版本与状态，`terminal-security` 管理主密钥/包认证与可恢复重加密，`terminal-storage::official_sync` 负责稳定 ID 合并和差异事务；Vue 只接收轻量状态。同步命令统一注册 AppManifest、handler 与 ACL，读取/手动同步仅本地 main/settings，完成门禁仅 main，不能扩大通用会话 owner。

需要运行验证：全新/已有库/锁定库、错密码、退出保留数据、跨账号基线隔离、双设备增删改/凭据配套/信任冲突、409/丢响应、离线重启、无变化同步、改密并发/超时/取消/断电/磁盘满、云端和本地不同密码时恢复，以及三平台钥匙串与协议回跳。新增回归用例尚未执行；已应用迁移不可改写，客户端新增迁移 6（schema 7），服务端新增迁移 004。

2026-10-19 决策：官方采用单头全量密文、稳定 ID 三方合并与 CAS，第三方保留独立手动版本备份。区分两种模式的密码和入口，移除第三方首次启动初始化路径，减少两套启动恢复流程并存的复杂度。
