# 产品需求与实现状态

日期：2026-10-17。需求、源码实现状态与当前限制统一维护于本文；运行验收单独说明。

## 1. 产品定位

Termeta 面向需要频繁连接服务器的开发、运维和设备工程师。首期提供本地优先、无需账号、凭据由用户控制的桌面 SSH 工作台；长期对标 Termius 的主机管理、终端、文件传输和连接工具体验。Termius 官网公开展示 SFTP、Snippets、端口转发等能力，但本项目按自己的里程碑交付，不承诺一次覆盖其全部产品。[产品参照](https://www.termius.com/)

## 2. 平台与非目标

| 平台    | 计划发布范围              | 待确认项                                 |
| ------- | ------------------------- | ---------------------------------------- |
| Windows | Windows 11 x64 + WebView2 | Windows 10、ARM64 以后评估               |
| macOS   | Apple Silicon 与 Intel    | 最低系统版本由 Tauri/WebKit/依赖实测确定 |
| Linux   | 优先 Ubuntu 24.04 LTS x64 | WebKitGTK、发行版打包、Wayland/X11 实测  |

这是初始验证矩阵，并非已通过的支持声明。只考虑桌面端；Android/iOS、浏览器远程终端服务、内嵌 SSH 服务端不在范围。首期不包含 Mosh、AI、自动双向云同步、团队权限、插件市场、跨重启保活和终端会话回放。

用户触发的 Gist / WebDAV 加密快照备份、下载预览与非覆盖合并已纳入 DATA-03 的源码实现；首次设置密码时也可拉取云备份并保存本机云端配置。它不包含多设备自动拉取、融合和双向同步，详见[备份与同步](22-data-backup.md)。

## 3. 用户场景

1. 用户创建主机、选择密码或私钥，核验首次指纹后进入远端 Shell。
2. 同时打开多个服务器终端，在标签间切换，远端任务与屏幕缓冲持续存在。
3. 连接超时、失败或中断时保留原 Tab 与终端，历史仍可滚动/复制/搜索；手动重连创建新后端连接，在原终端继续追加输出，不重放已有输入。
4. 重启应用后保留主机、分组、偏好与历史；不自动连接、不宣称恢复远端 Shell；首次设置保险库密码后，主机配置及凭据统一存入AES-256加密数据库，OS凭据库只保存一把主密钥；后续优先自动解锁，失败则密码恢复并重存主密钥。
5. 在同一终端框架内打开本地 PTY、串口或 Telnet；串口当前为文本模式，原始字节 HEX 查看器尚未实现。
6. 手动将业务数据加密上传到 Gist/WebDAV，或选取云端版本预览后新增导入；新设备首次初始化可直接拉取备份，应用设置继续使用本机配置。

分组删除先选择处理方式：默认只删除当前组并把直属主机/子分组移动到父级；选择一并删除会展示子树/主机数量并独立二次确认，Rust事务删除整棵子树和主机、登记专属密码清理；共享凭据与已有会话不受影响。删除主机清理其专属密码，不删除共享凭据，也不自动关闭已经建立的会话。

“断开连接”与“关闭 Tab”是两个操作：前者释放后端连接但保留视图与历史，后者由用户明确触发并释放视图。历史保留受已配置的 scrollback 上限约束，不因重连额外裁剪；终端正文不跨应用重启持久保存。错误提示不得用整页遮罩阻止滚动或复制。

## 6. 非功能要求

- 可靠性：输出不得静默截断；重连与写入不可自动重试导致命令重复执行；清理有时限与可观测结果。
- 安全：默认拒绝未知/变更密钥，用户明确确认后才信任；密码和私钥不以明文落盘。默认关闭弱算法、Agent forwarding、OSC52 剪贴板写入。
- 性能：限制滚屏、并发会话、流缓冲及输入大小。初始待测目标为启动 ≤2 秒、低延迟网络新增交互开销 p95 ≤20 ms、可见终端 ≥2 MiB/s 持续60秒且高输出10分钟无持续线性内存增长、20会话（5个持续输出）仍可操作、单普通会话进程树 ≤200 MiB/10会话 ≤500 MiB、取消关闭 p95 ≤3秒。所有指标在真实三平台测量前只称“目标”。
- 隐私：默认无账号、无遥测、无会话内容日志；错误报告不包含凭据或完整终端内容。
- 可维护性：协议核心不依赖 Tauri；一个统一生命周期和数据通路；业务变化同步文档。
- 可用性：终端内容支持 UTF-8，UI 首期中文；显示文案集中管理，预留 i18n，不把多语言平台建设设为前置。

## 7. MVP 完成定义

M2 的 P0 需求全部落实且通过授权后的验证矩阵，至少完成三平台的连接、认证、密钥拒绝、resize、长输出、取消、关闭、重连和存储持久化。仅跑通一个 SSH 样例不算 MVP；仅有设计文档也不算功能实现。无法覆盖的平台或认证格式必须列出限制，不能用“russh 支持”代替应用验证。

### 8.2 生命周期与资源边界

- 备份只在 Rust 中生成/解密白名单 SQLite 快照，上传不覆盖已有版本，导入不覆盖已有记录；信任冲突保留本机并提示。应用设置、历史、云端凭据和现有会话不从备份覆盖；首次配置与业务导入同事务提交。格式、内存/远端限额及短期令牌见[备份与同步](22-data-backup.md)。

- core 每个 SessionManager 最多20活动/4建立并发；壳分别持有终端、文件、转发 manager，不能将限额相加解释为已验证承载能力。
- 终端数据面使用24字节帧头、32 KiB 帧、256 KiB 信用、512 KiB 输出预算、64 KiB 输入，解析后累计 ACK；正文不进入 Pinia/数据库/日志。
- 连接历史合计仅保留 SSH/Telnet/Local/Serial 最近20次连接尝试，不按主机去重；终端滚屏不受历史摘要裁剪影响。独立文件/转发连接不新增终端历史。
- SFTP 每页100项、视图10000项、64 KiB块，全局4传输/单浏览器1操作；侧栏隐藏保活，断开取消。上传确认覆盖与目录合并可留下部分目标，下载拒绝覆盖。详细授权/拖放/目录限制见 [SFTP](16-sftp-workspace.md)。
- 每条转发最多64流、远程待接收32项；停止/窗口关闭/心跳失联取消独立连接及子任务。删除主机保留失效规则供重选，不持久化运行状态。见 [端口转发](21-port-forwarding.md)。
- 保存工作区最多64窗格/32层，仅持有连接引用；不保存秘密、会话、输出或广播状态。见 [工作区存档](18-terminal-workspaces.md#8-显式保存与替换工作区)。
- 远端滚轮按源 xterm 实际生成的最终动作逐次广播，接收端不再累积 DOM 滚动量；当前组未聚焦的非命令窗格也可作为来源，键盘/粘贴仍受焦点约束。滚轮敏感度固定为2，源端增量两倍累积，历史滚动沿用同一敏感度，广播目标不重复加速；用户已确认所测场景多终端滚动同步，两倍敏感度体验、完整双向速率与各鼠标协议仍待验收。详见[工作区输入广播](18-terminal-workspaces.md#5-工作区输入广播)。
