# 开发路线

更新：2026-10-28。功能状态集中维护在 [产品需求](01-product-requirements.md)；本文只维护剩余实现的依赖和顺序。

## 1. 实现顺序

| 顺序 | 范围 | 前置边界 |
| --- | --- | --- |
| 1 | 收敛 Rust 保存项类型、文件扫描/执行与双端设置契约 | 保留现有数据库、备份和 IPC 表示；按实际重复职责重构，见 [结构评估](27-architecture-refactoring.md) |
| 2 | M2：专门的睡眠恢复、整库与元数据配对的本地自动备份 | 不重放输入；恢复不得破坏现有会话、保险库和密钥元数据 |
| 3 | M3：本地文件端点、完整同远端/本地复制、连接租约与通用任务管理、侧栏尺寸持久化 | 本地端点不依赖 PTY；先明确连接持有、取消、部分失败和本地路径授权，再扩展复制方向 |
| 4 | M3：ProxyJump、Agent、SSH config/known_hosts 导入 | 沿用现有信任、凭据及 owner 边界，不默认启用 Agent forwarding |
| 5 | M4：自定义 Local Shell/cwd/env、完整进程树清理；串口控制线、HEX 与发送工具 | 复用会话生命周期；原始字节不混入文本转码通道 |
| 6 | M4：启动偏好、本地 CLI/cwd/argv 与请求转交 | 保持解锁门禁、显式请求优先及结构化参数；不拼接 Shell 字符串 |
| 7 | M5：签名、公证、更新和诊断流程 | 同步处理 [依赖风险](02-library-research.md#4-已知依赖风险)、[待迁移依赖](28-dependency-upgrade-plan.md) 与资源许可，保持保险库配对恢复能力 |

前两类结构工作不要求新增 crate、连接池或通用执行框架。文件任务从一个实际复制方向逐步收敛，避免为未来能力建立空模块。

## 2. 扩展约束

- dev 只提供 CLOUD 数据库升级兼容，不包含 CLOUD 产品功能。schema 10 可原位升至 11；返回 cloud 前必须同步相同编号、原始字节的迁移及 schema 支持，不能交给仍只识别 schema 10 的版本。dev/cloud 后续迁移继续保持编号和原始字节一致，保留 SQLx 严格校验；未知迁移和未来 schema 不在当前兼容范围。
- 数据库驱动与引擎升级沿用 SQLCipher 4 兼容格式和现有业务 schema；新增业务结构通过新增迁移交付，不能由依赖版本变化推导数据库迁移。
- 自动恢复打开标签与显式工作区存档分开设计，不恢复秘密、终端正文或未确认输入。
- 文件覆盖、目录合并及批量操作保留部分失败语义，不承诺回滚；持久化队列、断点续传与跨重启任务恢复另行定义。
- 第三方自动双向同步、团队、远程编辑、独立批量执行与系统后台热键属于后续范围，先定义权限、资源生命周期和冲突处理。
- Windows 默认终端委派独立于普通 CLI 入口，不通过启动本地 Shell 隐式获得系统终端关联能力。
