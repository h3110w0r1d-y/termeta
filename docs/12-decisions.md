# 架构决策记录

基线日期：2026-10-15。已采纳表示方向确定，不表示集成已验证。关键变更追加记录，保留旧决策的替代关系。

## ADR-001：桌面端、SSH 优先

状态：已采纳。

原因：用户已有桌面 Tauri 项目，首期允许只做 SSH。决定先交付 SSH 纵向切片与 MVP，不把 Local PTY 或串口设为前置，不规划 Android/iOS。长期参照 Termius 核心功能，但云/团队另立项。

后果：core 与数据面保留扩展，具体 Local/Serial crate 等对应需求开始再创建。若范围改变，先改产品需求与路线。

## ADR-002：沿用 Vue，不切换前端框架

状态：已采纳。

保留 Tauri 2 + Vue 3 + TypeScript + Vite。Pinia 只管轻量业务状态，xterm 与流缓冲由非响应式 registry 管理。2026-10-15 补充评估后，UI 采用 Reka UI primitives + 项目封装组件 + CSS tokens/自定义样式方向；Tailwind 可选。具体 release/集成待验证，细节见 ADR-013 与 13 文档。

理由：现有模板一致，降低初始化/迁移成本；没有证据要求 React 或复杂 Dock 库。M3 分屏是否采用第三方布局库再按 Vue 生态评估。

## ADR-003：Rust workspace 与单向依赖

状态：已采纳方向，目录迁移未执行。

core 定义会话模型/管理与端口；ssh/storage/security 适配；Tauri 壳组装。核心不依赖 Tauri，不直接引用 UI 或具体数据库。未来新增传输不复制三套 SessionManager。

迁移时统一根 Cargo profile/lockfile 和 workspace resolver，验证 Tauri 相对路径；不能仅移动文件后声称架构完成。

## ADR-004：russh 作为 SSH 主引擎

状态：条件采纳，SP-01/05 未通过前不冻结具体版本。

理由：异步 Tokio、可直接控制认证/信任/PTY/channel，便于未来专业 SSH。ssh2 为可行备选但需要额外阻塞/非阻塞适配；系统 ssh 命令不作默认后端，因为交互解析、跨平台依赖、主机信任和认证治理更复杂。

变化条件：在同一固定 release 中发现无法满足关键认证/取消/背压或平台构建要求且无可接受修复时重新评估。不能为保留库而去掉主机密钥校验。

## ADR-005：每会话 actor，不用大锁包协议对象

状态：已采纳。

理由：统一生命周期和输入顺序，避免 `Arc<Mutex<dyn Session>>` 长读阻塞写入/关闭。采用对象安全工厂/driver，driver Send 单任务拥有；关闭信号独立于输入队列；输出转发与协议控制分离。

代价：必须明确任务汇合、库内部队列与取消，不能仅套 async_trait 就认为并发问题解决。

## ADR-006：原始字节 Channel + 应用 ACK

状态：采纳协议方向，raw bridge 与性能待 SP-02 验证。

决定用 Tauri 双 Channel 分离控制与数据；输出二进制帧 v1、累计字节 offset、xterm 解析回调 ACK、有界信用；输入串行命令保序。不增加 WebSocket，不将终端输出存入 Vue 状态或 DB。

理由：Channel send 成功不等于 WebView 消费完成；仅 Rust mpsc 有界仍可造成 WebView 积压。代价是帧/ACK/交错终态需要验证。若 raw bridge 不符合目标，修改 ADR 与协议并经过对比，不能悄悄改成无限 JSON 事件。

## ADR-007：安全凭据和主机信任分离

状态：已采纳策略；后端包组合待 SP-03。

密码/私钥口令存系统凭据库，SQLite 只存元数据引用；私钥首期保留用户文件引用。候选采用 keyring-core + 平台后端，避免照搬旧 keyring 3.x 配置。服务不可用允许本次不保存，禁止明文回退。

主机公钥不是秘密，可在 SQLite 保存完整 pin 与核验元数据；首次明确确认，变更阻断。不能把“凭据安全存储”误当成“主机身份校验”。

## ADR-008：SQLite + SQLx，通用 profile + 协议扩展表

状态：已采纳方向，SP-04 待执行。

不让前端执行 SQL。统一 connection_profiles，SSH 搜索字段与认证引用结构化存储；配置 JSON 只放低频非秘密选项且版本化。使用 migration、WAL 下可靠备份与跨凭据库补偿；不提前创建所有未来表。

代价：多表及凭据一致性比单个 JSON 文件复杂，但可以明确约束、搜索与扩展。若首期 SQLx 依赖阻碍接入，可在 repository 后替换实现，仍须迁移与数据保护，不改变秘密边界。

## ADR-009：重连新建后端连接，复用原终端与历史

状态：已采纳。

2026-10-15 按用户明确要求修订：断线、连接失败、认证失败、正常远端退出都保留原 Tab、terminalId、xterm 实例与有限滚屏缓冲，历史可滚动/选择/复制/搜索；不得自动关 Tab、清屏或销毁视图。重连只替换后端 requestId/sessionId/Channel，先处理旧流边界，再在原终端追加新输出。修订前“新缓冲/新视图”的描述已被替代。

重连重新握手/校验/认证，清空的只有旧待发送输入，不自动重放；新旧帧/ACK/状态按连接代次隔离。后端终态和 tombstone 淘汰不结束前端终端生命周期。布局恢复只恢复引用，默认不自动连接；显示历史的延续不保证原远端 Shell 恢复，后者依赖 tmux/screen 等远端能力。后台标签继续解析/ACK，切换不销毁终端。

## ADR-010：SFTP/隧道不是通用终端能力

状态：已采纳边界，M3 租约设计见 16，尚未实现。

首期一个 session 一个 SSH connection；未来 connection service 为 Shell/SFTP/forwarding 分配独立 channel 与受控租约，最后租约释放后断开。不给 core 通用终端加入文件 API/端口监听 API，也不提前实现跨主机连接池。

变化条件：M3 的公平性/背压验证若显示共享连接造成不可接受的互相阻塞，可选择独立连接策略，并明确认证/信任与 UX 影响。

## ADR-011：Local/Serial 保留接口，后续再冻结库组合

状态：已采纳。

portable-pty 为 Local 首选候选；serialport 或 tokio-serial 为 Serial 候选。长期阻塞读采用可退出的独立线程或可靠异步适配，不用 abort spawn_blocking 伪装取消。Serial 不具备 resize/PTY，原始字节进入 Terminal 或 HEX 显示，不强制所有数据 UTF-8。

## ADR-012：禁止主动构建/运行，验证状态诚实记录

状态：用户约束，必须遵守。

未经用户明确要求，不构建/启动项目，不用 cargo check/test/clippy、自动工作流或浏览器启动等间接绕过。当前可以静态审阅、改代码/文档、设计验证；没有执行的编译/运行标记为待验证。功能/架构改动同轮更新 AGENTS.md、路线和相关 docs。

2026-10-15 按用户补充修订：开发所需依赖安装/更新、必要工具下载、锁文件更新及不构建/运行项目的静态检查允许主动执行，无需单独确认；安装生命周期脚本不得间接构建/运行项目。新增或修改的代码注释使用中文，API 名称/标识符保持原文。

此约束不禁止用户后续授权具体验证；一旦授权按实际范围执行并记录结果，不重复索要已明确授权的步骤。

## ADR-013：Reka UI 作为桌面交互基础控件

状态：采用方向，版本与三平台集成待 SP-07；尚未安装。

原因：用户希望高度自定义并适合桌面应用。官方无样式/组合/受控状态能力适合项目设计系统；Dialog、Menu、Tooltip、Select 等覆盖常见交互。采用 `src/components/ui/` 隔离封装，CSS tokens 管理紧凑密度和主题，原生菜单/文件选择由 Tauri 提供。

边界：Reka 不拥有终端生命周期，不提供本项目的完整 Dock/拖拽工作区；Tabs 隐藏不得卸载终端；Tree 文档标 Alpha，需隔离验证，不能直接承诺稳定。视觉设计和业务交互由项目完成，不叠加第二套完整预设风格组件库。详见 [UI 选型](13-ui-stack.md)。

## ADR-014：统一命令与两类自定义快捷键

日期：2026-10-15。状态：已采纳，M2 实现待开始。

按用户要求设置分应用内全局与终端动作，支持键盘和修饰键+点击、多绑定/禁用/恢复/导入导出。CommandRegistry 统一按钮/菜单/快捷键，Router 按焦点/IME/模态路由且不重复触发。全局默认应用前台，OS 后台热键独立 opt-in。Cmd+L 为新本地终端默认值，Local M4 工厂未实现时禁用；不能借此提前提供未治理的系统 Shell。详见 [14](14-shortcuts.md)。

## ADR-015：终端方案独立于应用主题

日期：2026-10-15。状态：已采纳，M2 实现待开始。

至少 8 内置配色、完全自选颜色/ANSI 与 JSON 导入导出，项目 schema 转换 xterm ITheme；应用 UI 明暗与 Terminal scheme 分开。全局/profile/当前终端选择按优先级解析，热更新不重建/清空实例，不保证重映射远端显式 truecolor。导入不执行代码、不自动覆盖。详见 [15](15-terminal-themes.md)。

## ADR-016：共享文件服务、双入口与有界远端中转

日期：2026-10-15。状态：已采纳方向，M3/SP-10/11 待实现验证。

SSH 终端可配置左/右/底部的 SFTP 面板；另有左右两侧均可选本地/SSH 的独立 SFTP Tab。FileProvider/TransferManager 与 TerminalSession 分离，独立 SFTP 不启动 Shell，本地文件不依赖 PTY。默认远端到远端经客户端有界内存中转，不默认落盘，也不依赖远端 scp。

所有上传及其他目标写入默认检查/询问覆盖，预检与发布复核，按服务器能力安全创建/替换；不宣称通用原子条件覆盖、不自动删旧文件兜底。属性按协议能力处理。外部原生拖出与内部 DnD 分开，staging+原生拖出为候选，必须三平台验证；不支持处说明限制，不能声称已完整交付。详见 [16](16-sftp-workspace.md)。
