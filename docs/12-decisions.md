# 架构决策记录

最后更新：2026-10-15。仅保留当前有效决策与必要的替代关系；“采用”表示源码或方向确定，不表示运行验收通过。

## ADR-001：桌面端、SSH 优先

支持 Windows/macOS/Linux，首期 SSH，后续 Local/Serial；不规划移动端。长期参照终端产品核心体验，云/团队另行立项。避免未来功能阻塞 SSH 纵向交付，不提前创建空 crate。

## ADR-002：沿用 Vue，不切换前端框架

采用 Tauri 2 + Vue 3 + TypeScript/Vite。Pinia 只保存轻量状态，xterm/流缓冲由独立 registry 管理。Naive UI 优先原则见 ADR-021，自定义工作区标签为例外。

## ADR-003：Rust workspace 与单向依赖

已建立 core/ssh/storage/security/files/sftp 六个领域 crate，由 Tauri 壳注入并管理根 Cargo.lock/profile。core 不依赖 Tauri/russh/Vue；秘密、协议与文件正文由 Rust 处理，IPC 门面是前端唯一原生入口。

## ADR-004：russh 作为 SSH 主引擎

源码采用 russh 0.64.1（ring+rsa），便于控制认证、信任、PTY/channel 与异步取消。不采用解析系统 ssh 交互作为默认后端。若固定版本无法满足认证、背压、取消或平台要求再评估备选，不能为兼容库取消主机密钥校验。具体组合运行验证仍待执行。

## ADR-005：每会话 actor，不用大锁包协议对象

driver 由单任务拥有，会话输入有界保序、关闭信号独立，输出转发与协议控制分离。不在全局锁内等待网络/DB/Channel；不能让 ACK 堵塞关闭、KeepAlive 或信任响应。代价是必须验证任务收尾与库内部队列。

## ADR-006：原始字节 Channel + 应用 ACK

采用控制/数据双 Channel，二进制帧、累计 offset、xterm 解析回调 ACK 和有界信用。send 成功不等于 WebView 消费；不使用无限 JSON 输出或把正文放入响应式状态/DB。新旧流与终态/finalOffset 按代次隔离，性能与竞态待验收。

## ADR-007：安全凭据和主机信任分离

秘密存 OS keyring，SQLite 只存元数据/引用，无明文回退或通用取秘密 IPC。主机公钥独立持久化，首次明确确认，变更阻断；凭据存储不能替代身份校验。具体凭据模型见 ADR-022，平台后端见 ADR-017。

## ADR-008：SQLite + SQLx，通用 profile + 协议扩展表

Rust repository 管理结构化主机/信任/设置，不允许前端 SQL，不提前创建未来表。当前为独立 schema 1 基线；不兼容旧库的路径隔离见 ADR-022。未来迁移、WAL 备份和跨 keyring 补偿必须保持数据保护。

## ADR-009：重连新建后端连接，复用原终端与历史

断线/失败/正常退出保留 Tab、terminalId/xterm 与有限历史；重连重新握手/校验/认证，仅替换 session/Channel，不清屏、不自动重放输入。旧流先收尾，新旧字节/ACK/状态隔离；隐藏终端继续消费 ACK。全屏保留有界可读文本快照，不保证样式或远端 Shell 恢复。

## ADR-010：SFTP/隧道不是通用终端能力

SSH 服务为 Shell/SFTP/forwarding 管理独立 channel，不给通用终端接口塞文件或监听 API。当前 SFTP 通过 owner-bound SshChannels 复用认证连接，生命周期仍跟随 Shell；独立连接租约和 SFTP-only 尚未实现。共享连接公平性不达标时可评估独立连接及其认证影响。

## ADR-011：Local/Serial 保留接口，后续再冻结库组合

Local 首选 portable-pty 候选；Serial 候选 serialport/tokio-serial。阻塞读取必须能退出，不以 abort spawn_blocking 伪装取消。Serial 不具备 PTY/resize，字节可进入终端或 HEX 视图，不强制 UTF-8；真实硬件验证后才能承诺兼容。

## ADR-012：禁止主动构建/运行，验证状态诚实记录

未经用户明确要求不编译/启动/运行测试/连接主机，也不间接绕过；允许必要依赖与工具、锁更新和无构建静态检查，安装须避免生命周期构建。注释使用中文，实现同轮同步相关文档。静态通过不替代运行证据；已有明确授权不重复询问。

## ADR-014：统一命令与两类自定义快捷键

已实现 CommandRegistry 与应用内全局/终端快捷键，按焦点/IME/模态路由，支持多绑定、录制、禁用、恢复和 JSON。OS 后台热键独立 opt-in，尚未实现；Local 工厂不可用前禁用 Cmd+L 动作。代价是键盘布局/AltGr/菜单去重需三平台专项验证。

## ADR-015：终端方案独立于应用主题

全局/主机/当前终端按优先级解析，热应用不重建或清空 xterm。内置只读、自定义可编辑，JSON 只解析数据、不执行代码或静默覆盖；显式 truecolor 不保证随 ANSI 配色重映射。当前资源与默认值见 ADR-024。

## ADR-016：共享文件服务、双入口与有界远端中转

目标为终端附属面板与独立双栏共用文件服务，独立 SFTP 不启动 Shell、本地浏览不依赖 PTY；远端互传默认客户端有界内存中转，不默认落盘或依赖 scp。当前只交付附属右栏，双栏/端点授权/租约/互传仍待实施。原生拖出不能用网页 DnD 冒充，详见 ADR-028。

## ADR-017：首期实际依赖与凭据适配

采用 keyring 3.6.3 显式平台后端：macOS apple-native、Windows windows-native、Linux sync-secret-service/crypto-rust。CredentialStore 隔离实现，OS 调用使用专用阻塞工作器，不在全局锁等待；服务缺失显式失败，不 mock 或明文降级。

依赖固定 release/锁文件并复核源码 API、features、许可证/MSRV；当前 RSA/GLib 和停止维护公告未关闭，详见 [公告记录](17-implementation-status.md#4-依赖与公告核查)。依赖解析或编译成功不能替代安全审阅。

## ADR-018：首期设置聚合与凭据保存边界

配色/keymap/hostSchemes 存版本化 app JSON，Rust 校验白名单/容量/引用；只允许 main 窗口，不提前建立独立表或多窗口 revision。认证 challenge/OTP 只用于本次，凭据保存独立进入主机/凭据用例，不把远端提示当可保存秘密。

## ADR-020：应用固定标签与自动交互认证（2026-10-15）

首页/SFTP 固定不可关闭，SSH 随后；顶部/左侧布局持久化，首页内主机/凭据/设置保活，固定页不创建 session/xterm。密码/公钥是主要认证方式，后端依服务器方法/partial success 衔接 Keyboard-interactive；challengeId 单次消费，不提供用户手动追加 OTP 的静态流程。

## ADR-021：统一 Naive UI 与两种主要认证方式（2026-10-15）

Naive UI 固定 2.45.3。通用控件和主题直接采用库能力，薄封装只适配值/事件/布局；自定义 WorkspaceTabs、xterm 与原生文件授权为必要边界。标签显隐不拥有终端生命周期，CSS-in-JS 不放宽脚本权限。认证主选项限定密码/公钥，动态交互由后端协商。

## ADR-022：公共凭据与主机专属密码（2026-10-15）

公共凭据为密码/私钥，私钥正文和可选解密密码同存 OS item，导入后不依赖原文件。主机引用公共项或使用专属密码：非空保存、显式空移除后连接询问、省略保留，无记住开关；复制不复制专属密码，公共 DTO 只返回 hasPassword。

owner_profile_id 隔离专属项；pending/ready/deleting、新项先写/事务绑定/旧项后删处理跨存储失败，已提交后清理失败不伪报未保存。OTP 不持久化，不提供返回秘密的接口。

当前使用独立 `termvexa-credentials-v1.sqlite3`、schema 1，不迁移/删除旧 `termvexa.sqlite3` 或真实 OS item，不绕过高版本/校验和保护。首次新库为空，较大私钥容量、OS 故障与恢复仍需三平台实测。

## ADR-023：固定内置终端字体（2026-10-15）

随包分发 12 字体及来源/许可证/摘要，默认 DejaVu Sans Mono；不依赖 CDN 或系统字体。前后端白名单，无效旧名字回退默认。字体就绪后重测既有终端尺寸，不销毁历史；字宽、加载与包内许可待平台验证。

## ADR-024：用户提供的配色数据作为内置资源（2026-10-15）

静态提取 64 套颜色为共享 JSON，默认 Pro；补足缺失字段，不执行来源代码。Rust/TS 共用数据，旧明暗引用归一、用户自定义保留。来源未确认独立开源授权，不附加未经证实的许可声明，发布前处理来源风险。

## ADR-025：标签组与终端分离，纯数据树计算分屏（2026-10-15）

tabs 保存终端元数据，groups 管布局/顺序/聚焦，二叉树计算矩形、扁平 keyed 宿主保活。Pointer Events 处理排序/四向分割/比例与窗格拖回 Tab/跨组重排；600 ms 悬停切组，不移动 xterm DOM。关闭组与窗格不同，固定页独立；整组迁移、跨窗口和布局保存未实现。

远端 OSC 标题只作有界非持久化展示；关闭提示组合 OSC 133 执行阶段与首次标题比较，是启发式而非前台进程证明。

## ADR-026：当前Workspace用户输入广播（2026-10-15）

组内存共享开关默认关闭，成员重组关闭，排序/比例调整保留。inputOrigin 隔离固定 xterm 6.0.0 内部用户输入事件只读订阅；缺能力拒绝开启。inputRouter 分发键盘/IME/独立编码粘贴和远端滚轮，排除点击/拖动/自动应答/认证与普通历史滚动。

粘贴确认一次并绑定组版本/目标连接代次；失效取消，不重放。代价是一处内部 API 兼容边界，升级与三平台真实 Shell/vim 必须专项验收。

## ADR-027：先落地单SSH终端SFTP，独立双栏延后（2026-10-15）

SFTP 范围为浏览、上传和下载。单 SSH 终端底部开关控制可调右栏，Workspace 无效；开启侧栏可排序但不能作为分屏来源或目标，统一由 canSplit 限制。隐藏保留浏览和传输，关闭/断线结束任务；固定双栏仍占位。

files/sftp 分层，sessionId 授权远端，正文只在 Rust 64 KiB 流动。每页 100 项、包 256 KiB、视图 10000 项；链接保留自身 kind 并用 READLINK/STAT 识别目标，导航使用逻辑绝对路径，只有初始目录调用 REALPATH。目录链接可直接访问 `/bin/...`，不先展开到目标；源链接不递归传输。

## ADR-028：直接上传覆盖、目录合并与原生拖放（2026-10-15）

按用户要求，上传直接写最终文件；同名普通文件逐项原生确认才截断，新目标独占创建。目录只合并，不删除/替换目录；树内链接与特殊文件拒绝。上传不依赖远端 hardlink，代价是中断可能留下不完整文件、不能回滚；SFTP v3 无通用 NOFOLLOW/条件写入，类型核对不能完全消除并发路径替换竞态。

OS 拖入在 Rust 登记 owner-bound 短期一次性引用，前端确认当前侧栏目录后入有界批次，不接受任意本地路径。macOS 用 NSFilePromiseProvider：外部接受并给出 URL 后才读取源和展示任务；Esc/内部松开不留下载记录，也不触发上传。拖出令牌由命令统一持有并显式传入原生层，禁止重叠命令隐式共享；原生 source 仅保活回调所需状态，命令等待写入退出并补齐 WebView 松键后再恢复交互。文件/目录后台串行兑现，递归 64 层/10000 项，不跟随链接，不替换已有本地目录；失败保留已下载内容。

下载仍以本地独占临时项+硬链接无覆盖发布；不支持硬链接时明确失败。Windows/Linux 原生拖出尚未实现，保留下载按钮；所有原生拖放均待运行验收。采用锁定 objc2/block2/AppKit/Foundation API，不以静态宏核对声称 Finder 行为通过。
