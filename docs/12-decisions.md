# 架构决策记录

基线日期：2026-10-15。已采纳表示方向确定，不表示集成已验证。关键变更追加记录，保留旧决策的替代关系。

## ADR-001：桌面端、SSH 优先

状态：已采纳。

原因：用户已有桌面 Tauri 项目，首期允许只做 SSH。决定先交付 SSH 纵向切片与 MVP，不把 Local PTY 或串口设为前置，不规划 Android/iOS。长期参照 Termius 核心功能，但云/团队另立项。

后果：core 与数据面保留扩展，具体 Local/Serial crate 等对应需求开始再创建。若范围改变，先改产品需求与路线。

## ADR-002：沿用 Vue，不切换前端框架

状态：已采纳。

保留 Tauri 2 + Vue 3 + TypeScript + Vite。Pinia 只管轻量业务状态，xterm 与流缓冲由非响应式 registry 管理。当前 UI 采用 Naive UI 2.45.3 现成组件与主题，Reka 旧选型已由 ADR-021 取代；详见 13 文档。

理由：现有模板一致，降低初始化/迁移成本；没有证据要求 React 或复杂 Dock 库。分屏后续按用户要求提前至 M2，采用纯数据二叉树与 Pointer Events，见 ADR-025。

## ADR-003：Rust workspace 与单向依赖

状态：已采纳方向，目录迁移未执行。

core 定义会话模型/管理与端口；ssh/storage/security 适配；Tauri 壳组装。核心不依赖 Tauri，不直接引用 UI 或具体数据库。未来新增传输不复制三套 SessionManager。

迁移时统一根 Cargo profile/lockfile 和 workspace resolver，验证 Tauri 相对路径；不能仅移动文件后声称架构完成。

## ADR-004：russh 作为 SSH 主引擎

状态：条件采纳，SP-01/05 未通过前不冻结具体版本。

理由：异步 Tokio、可直接控制认证/信任/PTY/channel，便于未来专业 SSH。ssh2 为可行备选但需要额外阻塞/非阻塞适配；系统 ssh 命令不作默认后端，因为交互解析、跨平台依赖、主机信任和认证治理更复杂。

变化条件：在同一固定 release 中发现无法满足关键认证/取消/背压或平台构建要求且无可接受修复时重新评估。不能为保留库而去掉主机密钥校验。

## ADR-005：每会话 actor，不用大锁包协议对象

状态：已采纳。

理由：统一生命周期和输入顺序，避免 `Arc<Mutex<dyn Session>>` 长读阻塞写入/关闭。采用对象安全工厂/driver，driver Send 单任务拥有；关闭信号独立于输入队列；输出转发与协议控制分离。

代价：必须明确任务汇合、库内部队列与取消，不能仅套 async_trait 就认为并发问题解决。

## ADR-006：原始字节 Channel + 应用 ACK

状态：采纳协议方向，raw bridge 与性能待 SP-02 验证。

决定用 Tauri 双 Channel 分离控制与数据；输出二进制帧 v1、累计字节 offset、xterm 解析回调 ACK、有界信用；输入串行命令保序。不增加 WebSocket，不将终端输出存入 Vue 状态或 DB。

理由：Channel send 成功不等于 WebView 消费完成；仅 Rust mpsc 有界仍可造成 WebView 积压。代价是帧/ACK/交错终态需要验证。若 raw bridge 不符合目标，修改 ADR 与协议并经过对比，不能悄悄改成无限 JSON 事件。

## ADR-007：安全凭据和主机信任分离

状态：安全边界继续采用；凭据模型已由 ADR-022 取代，后端包选型见 ADR-017。

密码/私钥口令存系统凭据库，SQLite 只存元数据引用；私钥首期保留用户文件引用。候选采用 keyring-core + 平台后端，避免照搬旧 keyring 3.x 配置。服务不可用允许本次不保存，禁止明文回退。

主机公钥不是秘密，可在 SQLite 保存完整 pin 与核验元数据；首次明确确认，变更阻断。不能把“凭据安全存储”误当成“主机身份校验”。

## ADR-008：SQLite + SQLx，通用 profile + 协议扩展表

状态：已采纳方向，SP-04 待执行。

不让前端执行 SQL。统一 connection_profiles，SSH 搜索字段与认证引用结构化存储；配置 JSON 只放低频非秘密选项且版本化。使用 migration、WAL 下可靠备份与跨凭据库补偿；不提前创建所有未来表。

代价：多表及凭据一致性比单个 JSON 文件复杂，但可以明确约束、搜索与扩展。若首期 SQLx 依赖阻碍接入，可在 repository 后替换实现，仍须迁移与数据保护，不改变秘密边界。

## ADR-009：重连新建后端连接，复用原终端与历史

状态：已采纳。

2026-10-15 按用户明确要求修订：断线、连接失败、认证失败、正常远端退出都保留原 Tab、terminalId、xterm 实例与有限滚屏缓冲，历史可滚动/选择/复制/搜索；不得自动关 Tab、清屏或销毁视图。重连只替换后端 requestId/sessionId/Channel，先处理旧流边界，再在原终端追加新输出。修订前“新缓冲/新视图”的描述已被替代。

重连重新握手/校验/认证，清空的只有旧待发送输入，不自动重放；新旧帧/ACK/状态按连接代次隔离。后端终态和 tombstone 淘汰不结束前端终端生命周期。布局恢复只恢复引用，默认不自动连接；显示历史的延续不保证原远端 Shell 恢复，后者依赖 tmux/screen 等远端能力。后台标签继续解析/ACK，切换不销毁终端。

## ADR-010：SFTP/隧道不是通用终端能力

状态：已采纳边界，M3 租约设计见 16，尚未实现。

首期一个 session 一个 SSH connection；未来 connection service 为 Shell/SFTP/forwarding 分配独立 channel 与受控租约，最后租约释放后断开。不给 core 通用终端加入文件 API/端口监听 API，也不提前实现跨主机连接池。

变化条件：M3 的公平性/背压验证若显示共享连接造成不可接受的互相阻塞，可选择独立连接策略，并明确认证/信任与 UX 影响。

## ADR-011：Local/Serial 保留接口，后续再冻结库组合

状态：已采纳。

portable-pty 为 Local 首选候选；serialport 或 tokio-serial 为 Serial 候选。长期阻塞读采用可退出的独立线程或可靠异步适配，不用 abort spawn_blocking 伪装取消。Serial 不具备 resize/PTY，原始字节进入 Terminal 或 HEX 显示，不强制所有数据 UTF-8。

## ADR-012：禁止主动构建/运行，验证状态诚实记录

状态：用户约束，必须遵守。

未经用户明确要求，不构建/启动项目，不用 cargo check/test/clippy、自动工作流或浏览器启动等间接绕过。当前可以静态审阅、改代码/文档、设计验证；没有执行的编译/运行标记为待验证。功能/架构改动同轮更新 AGENTS.md、路线和相关 docs。

2026-10-15 按用户补充修订：开发所需依赖安装/更新、必要工具下载、锁文件更新及不构建/运行项目的静态检查允许主动执行，无需单独确认；安装生命周期脚本不得间接构建/运行项目。新增或修改的代码注释使用中文，API 名称/标识符保持原文。

此约束不禁止用户后续授权具体验证；一旦授权按实际范围执行并记录结果，不重复索要已明确授权的步骤。

## ADR-013：Reka UI 作为桌面交互基础控件（已被 ADR-021 取代）

状态：采用方向，版本与三平台集成待 SP-07；尚未安装。

原因：用户希望高度自定义并适合桌面应用。官方无样式/组合/受控状态能力适合项目设计系统；Dialog、Menu、Tooltip、Select 等覆盖常见交互。采用 `src/components/ui/` 隔离封装，CSS tokens 管理紧凑密度和主题，原生菜单/文件选择由 Tauri 提供。

边界：Reka 不拥有终端生命周期，不提供本项目的完整 Dock/拖拽工作区；Tabs 隐藏不得卸载终端；Tree 文档标 Alpha，需隔离验证，不能直接承诺稳定。视觉设计和业务交互由项目完成，不叠加第二套完整预设风格组件库。详见 [UI 选型](13-ui-stack.md)。

## ADR-014：统一命令与两类自定义快捷键

日期：2026-10-15。状态：已采纳，M2 实现待开始。

按用户要求设置分应用内全局与终端动作，支持键盘和修饰键+点击、多绑定/禁用/恢复/导入导出。CommandRegistry 统一按钮/菜单/快捷键，Router 按焦点/IME/模态路由且不重复触发。全局默认应用前台，OS 后台热键独立 opt-in。Cmd+L 为新本地终端默认值，Local M4 工厂未实现时禁用；不能借此提前提供未治理的系统 Shell。详见 [14](14-shortcuts.md)。

## ADR-015：终端方案独立于应用主题

日期：2026-10-15。状态：已采纳，M2 实现待开始。

至少 8 内置配色、完全自选颜色/ANSI 与 JSON 导入导出，项目 schema 转换 xterm ITheme；应用 UI 明暗与 Terminal scheme 分开。全局/profile/当前终端选择按优先级解析，热更新不重建/清空实例，不保证重映射远端显式 truecolor。导入不执行代码、不自动覆盖。详见 [15](15-terminal-themes.md)。

## ADR-016：共享文件服务、双入口与有界远端中转

日期：2026-10-15。状态：已采纳方向，M3/SP-10/11 待实现验证。

SSH 终端可配置左/右/底部的 SFTP 面板；另有左右两侧均可选本地/SSH 的独立 SFTP Tab。FileProvider/TransferManager 与 TerminalSession 分离，独立 SFTP 不启动 Shell，本地文件不依赖 PTY。默认远端到远端经客户端有界内存中转，不默认落盘，也不依赖远端 scp。

所有上传及其他目标写入默认检查/询问覆盖，预检与发布复核，按服务器能力安全创建/替换；不宣称通用原子条件覆盖、不自动删旧文件兜底。属性按协议能力处理。外部原生拖出与内部 DnD 分开，staging+原生拖出为候选，必须三平台验证；不支持处说明限制，不能声称已完整交付。详见 [16](16-sftp-workspace.md)。

## ADR-017：首期实际依赖与凭据适配

日期：2026-10-15。状态：源码采用，集成待验证；细化/调整 ADR-004/007。

采用 russh 0.64.1（ring+rsa）、Tauri 2.11.5/build 2.6.3、SQLx 0.8.6、keyring 3.6.3 的显式平台后端。与前期 keyring-core 4.x 方向不同，本轮选择可核对源码的 3.6.3 adapter，macOS apple-native、Windows windows-native、Linux sync-secret-service/crypto-rust；不使用 mock，不把 OS 服务不可用降级到明文。独立 CredentialStore 允许将来替换该适配器，不影响领域和前端契约。私钥选择登记 SHA256 内容授权摘要，后续变化拒绝，摘要不等于 SSH 主机公钥指纹。

理由：先交付单一可审阅的业务适配器、明确 release/API/features，避免混用新版文档和旧配置。影响：SP-03/跨平台待执行；OS 操作不可强行取消，运行在专用阻塞池。Rust 公告查询发现 RSA/GLib 与停止维护条目，详见实施记录；未解决前不能宣称通过安全发布门槛。锁文件解析成功不代表安全或可编译。

## ADR-018：首期设置聚合与公开保存凭据用例

日期：2026-10-15。状态：源码采用，运行待验证；细化 ADR-008/014/015。

自定义配色、keymap 和 hostSchemes 存为版本化 app JSON，暂不创建独立颜色/主机偏好表与命令族。Rust 校验字段白名单、容量、引用和动作；前端在设置弹窗提交后统一应用。仅 main 窗口可调用，设置尚无多窗口 revision。后续多窗口/同步需求出现时新增 migration/use case，不能静默修改已发布 schema。

认证 challenge 固定 only-once，凭据保存独立为主机编辑中的 save_credential；避免把 OTP/任意服务器提示当成可保存秘密。新增 list/clear history、recover credential 用例同步 ACL。全屏结束保留有界纯文本快照，重连在同一 xterm 上追加，图形/样式精确保真不作当前承诺；需 SP-07 实测。

## ADR-020：应用固定标签与自动交互认证（2026-10-15）

原因：原主机栏常驻终端侧边、设置弹窗和手动追加 OTP 不符合用户预期。决定：首页与 SFTP 为最前两个不可关闭的应用 Tab，SSH 随后；提供顶部/左侧标签布局设置，首页内设主机/凭据/设置菜单。固定页不创建虚假终端，所有已打开的 xterm 独立保活。用户明确本轮 SFTP 仅双栏布局，实际文件服务仍为 M3。

此前认证方式选择密码、私钥或交互认证（现已由 ADR-021 收敛为密码/公钥）；删除用户控制的追加 OTP 字段，根据服务器 remaining_methods 与 partial_success 自动衔接 Keyboard-interactive，兼容旧认证计划且去重。秘密仍只在连接信任通过后读取，不自动保存交互答案。认证提示按 challengeId 消费，避免下一轮被迟到响应移除。

影响：新增 app.tabPosition，旧设置默认 top，无 migration/新增命令/依赖；同步前端设置类型和 Rust 白名单。状态为实现待验证；不将静态检查作为 macOS/WebKit 或 SSH MFA 验收。

## ADR-021：统一 Naive UI 与两种主要认证方式（2026-10-15）

用户明确放弃 Reka UI，并要求所有界面控件优先使用 Naive UI、尽量减少手写样式。决定固定 naive-ui=2.45.3，删除 reka-ui 及相关导入，使用 NConfigProvider 的现成深浅主题与中文 locale；Modal、Select、Input、Button、Checkbox、InputNumber、Tabs、Menu、ColorPicker、Collapse、Scrollbar 使用库组件。业务组件只保留必要值/事件适配和布局；不以 Primitive 包住原生控件冒充完整迁移。系统文件授权、隐藏 JSON 文件选择桥及 xterm 为必要边界。

主机/快速连接只提供密码和公钥认证。Keyboard-interactive 是后端协议过程，由服务器方法/部分成功自动触发。旧枚举保留反序列化兼容，纯交互旧记录编辑时显示密码，显式保存规范化为单个主要步骤。不新增 migration，不批量改写已有主机。

标签控件不拥有 xterm 生命周期；固定首页/SFTP 与动态会话分区保持可见，仍共用工作区状态。库未覆盖的跨区键盘导航只增加最小 ARIA/焦点适配。Naive UI CSS-in-JS 沿用已有样式 CSP 例外，脚本/ACL 不放宽。安装禁用生命周期脚本；运行与三平台验收未执行。

## ADR-022：公共凭据与主机专属密码（2026-10-15）

用户确认将可复用凭据改为密码和私钥，私钥拥有可选解密密码；不再单独保存 passphrase 类型。私钥由原生授权文件导入，正文与解密密码存于同一 OS item，SQLite 只存元数据，连接不依赖原文件。主机可引用公共凭据，或直接填写专属密码；非空保存即持久化，显式空值移除并改连接时询问，无记住开关。认证 challenge/OTP 仅用于本次。

决定以 owner_profile_id 隔离专属密码，公共列表/删除/恢复与临时连接不能越界；公共主机 DTO 仅暴露 hasPassword，不暴露专属 ID。收藏等元数据更新省略 password 时保留，主机编辑明确提交字符串。复制不复制专属密码，删除/切换认证登记删除任务，不误删共享凭据。

跨存储用 pending/ready/deleting 与新项先写、事务绑定、旧项后删；事务或 OS 写失败保留原配置，已提交后的清理失败只保留待重试状态，不伪报保存未提交。绑定事务直接产生保存结果，前端列表刷新与配色失败不得导致重试覆盖密码。专用凭据工作器串行化，不占 session 全局锁等待 OS。

用户明确不考虑旧数据库兼容迁移，本轮重建初始 schema 为1并移除0002；不迁移旧passphrase/静态KI步骤，不删除真实旧库或系统凭据。secret API 参数改变、core CredentialStore/认证步骤与 Rust/TS 同步，无新增IPC命令。security增加沿用锁版本的serde/serde_json/uuid依赖。系统凭据库单项容量（尤其较大私钥）与三平台行为仍待实测，失败不回退明文。本决策细化 ADR-007/017/018/021，状态为实现待验证。


### ADR-022 补充：新模型数据库路径隔离（2026-10-15）

用户运行反馈旧库版本 2 被新基线 schema 1 拒绝。新模型使用独立 `termvexa-credentials-v1.sqlite3`，保留旧 `termvexa.sqlite3` 与系统凭据，不自动迁移/删除，不绕过高版本和校验和保护。文件名代表凭据模型代际，不等于旧 migration 编号；首次进入新库为空，旧主机、设置、信任和凭据引用不自动带入。此方案落实不兼容旧库的范围决定，同时避免旧文件阻止新模型启动。


### ADR-023：固定内置终端字体（2026-10-15）

按用户要求，将系统自由字体输入改为12种固定本地字体，默认 JetBrains Mono。采用官方 release 或官方分发固定提交的未修改 TTF/WOFF2，随 public/fonts 原样分发许可证、版权、来源和 SHA-256；无运行时 CDN 或系统安装前提。Meslo 选择 LG S；经典 Ubuntu Mono 不替换为 Ubuntu Sans Mono。Naive UI 提供下拉交互；Rust 保存白名单，旧自由名称读取时回退默认项。字体就绪后更新既有 xterm、重测尺寸，不销毁终端；没有独立字型的家族由浏览器合成，不额外承诺连字。影响：安装资源增加约9.5 MB字体，加上许可等文件；三平台 WebView 字宽、加载时序与包内许可仍待验收。


### ADR-024：用户提供的配色数据作为内置资源（2026-10-15）

用户要求提取指定 Termius 解包应用的配色数据并移除项目原8套自有预设。静态解析64个对象的名称和终端颜色，记录数组/来源文件摘要，不执行解包代码。资源用单一 JSON 供 TS 与 Rust 读取，默认 Nord Dark；项目只补足源数据缺失的光标反色和失焦选区字段，分别复用背景与原选区值。旧预设明暗引用读取时归一，用户自定义方案不删除；终端生命周期与热应用保持原设计。来源集合未确认独立开源授权，不给提取数据附加未经确认的开源许可声明。

2026-10-15：按用户要求，工作区顶部/侧栏标签由 Naive UI Tab 改为自定义 WorkspaceTabs，便于后续实现拖拽排序和更多上下文操作。仅工作区标签作为 UI 库优先原则的例外；设置内标签与菜单等继续采用 Naive UI。组件不拥有会话或终端实例，不引入第二套排序/选中状态，当时未实现拖拽；当前实现见 ADR-025。

## ADR-025：标签组与终端分离，纯数据树计算分屏（2026-10-15）

按用户请求将标签排序与内存分屏提前至M2。保留tabs终端元数据，新增groups布局/顺序/聚焦状态；标签组不代表单一session，activeId与terminalId不可混用。采用二叉分割树和纯几何计算，在同一平面列表中保活终端宿主，避免递归组件搬动造成xterm重建。用Pointer Events实现同窗口排序/四向命中与分隔线调整，避免原生文件拖放差异，不新增Dock依赖。

影响：菜单/快捷键以聚焦叶子为目标，标签关闭处理整组，窗格关闭只处理自身；标签合并接受非激活单终端；窗格标题可拖回Tab或同组/跨组重分割，固定页独立。没有后端/IPC/秘密/数据库变更。内存布局不序列化，不实现组整体合并，布局持久化与恢复仍为M3。静态检查不代替三平台交互与生命周期验收。详见 [终端工作区](18-terminal-workspaces.md)。

ADR-025 补充（2026-10-15）：按用户要求补充窗格拖出。统一拖动来源为标签或窗格；标题是唯一窗格拖动入口，正文仍由xterm管理选择。跨标签采用600ms悬停切页而非移动/复制DOM，取消恢复活动组；纯数据迁移同时计算来源收缩和目标分割，同组重排先移除再插入，避免重复叶子。拖回Tab创建独立组ID，不能直接复用terminalId，因为来源组可能仍沿用此ID。所有操作只修改布局，整组迁移/跨窗口和布局保存仍留后续。

ADR-024 补充（2026-10-15）：默认终端配色按用户要求由Nord Dark改为Pro，采用现有共享资源ID `pro`，默认/回退与编辑基准继续共用前端常量；不改变已有显式设置与旧明暗预设映射，不修改提取色值。

## ADR-026：当前Workspace用户输入广播（2026-10-15）

按用户要求新增共享广播开关；进一步限定远端鼠标只转发滚轮，不转发点击/拖动。广播状态与版本保存在组内存，默认关闭，成员重组关闭；保持原终端/会话独立，沿用各会话FIFO与限额，不新增后端广播/IPC契约或持久化字段。

公开onData不能区分设备应答，onKey不能覆盖IME；在inputOrigin隔离对固定xterm 6.0.0内部onUserInput同步事件的只读订阅，不修改库方法/源码。公开onData紧随消费来源标记，缺能力拒绝开启广播。inputRouter只分发用户键盘/IME；鼠标报告排除，滚轮单独以合成WheelEvent交目标xterm处理其协议/尺寸，递归保护保证单次发送。普通历史滚动不广播。

粘贴只确认一次并展示目标数，目标分别使用公开paste编码，调用期抑制再次广播；保存组版本/目标代次，失效取消/跳过且不重放。代价为一处固定xterm内部事件兼容边界和DOM滚轮互通验证，升级需专项复验；不引入通用远程操作录制或跨主机执行同步协议。源码已实施，三平台/真实Shell与vim验收未执行。

字体默认值变更（2026-10-15）：按用户要求由JetBrains Mono改为DejaVu Sans Mono；覆盖前后端初始值及未知字体回退，不改写已有合法选择，不改变字体资源和加载机制。

OSC标题展示补充（2026-10-15）：按用户要求使用公开xterm标题事件提供标签后缀，不引入Shell脚本或输入命令猜测。保留原连接名称与Workspace身份，远端标题只作受限、非持久化展示；Workspace后缀跟随聚焦成员。

动态关闭提醒规则（2026-10-15）：按用户明确规则，OSC 133执行中直接提醒；否则仍回退比较本次连接首次OSC标题，而非让D等空闲标记完全覆盖标题判断。无信息视为无需提醒，保留现有confirmClose总开关。该组合为远端提示的启发式，允许漏报/误报，不替代真实前台进程查询。
