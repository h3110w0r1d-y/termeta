# SFTP 浏览、上传下载与双栏对拷

更新：2026-10-16。单 SSH 终端侧栏与固定双远端工作区已有源码，编译、真实 SSH 与原生拖放验收尚未完成。SFTP 范围为浏览、上传下载和双远端对拷。

## 1. 入口与生命周期

- 已连接的单 SSH 终端通过底部状态栏开关显示可调宽度的右侧栏；Workspace 中禁用。
- 开启侧栏的终端可以排序，但 `WorkspaceStore.canSplit` 禁止其作为分屏来源或目标；隐藏后恢复合并。
- 文件视图首次打开时挂载，隐藏保留目录、选择和任务。终端宿主以 margin 留白，侧栏不继承终端外层 padding；显隐由既有 ResizeObserver 驱动 fit/resize，不重建 xterm。
- 复用当前已认证 SSH 的独立 SFTP channel，不另启 Shell。隐藏继续传输，断开或关闭终端取消相关任务；重连使用新 sessionId，旧请求和任务不自动重放。
- 固定 SFTP Tab 为独立双远端工作区，从保存主机分别建立 SSH/SFTP 连接，不创建终端或启动 PTY/Shell。可选左侧/底部面板、本地浏览、通用共享连接租约尚未实现。

## 2. 目录浏览

列表列序为选择框、名称、大小、权限；名称前图标区分文件、目录和链接，链接显示原始目标。不显示类型和修改时间列。大小使用 BigInt，按 1024 进制换算 B/KB/MB/GB/TB，保留两位小数。

每页最多 100 个实际条目，跨 READDIR 包补齐并暂存余项；报文上限 256 KiB，单视图最多 10000 项，前端使用虚拟列表。目录及目录链接始终排在其他条目前，升降序只作用于组内。置顶 `..` 不计入分页、不参与选择，双击进入逻辑上级；根目录禁用。支持路径输入、主目录、上级、刷新和“显示隐藏文件”开关。该开关为全局偏好，终端侧栏和双栏共用；切换自动保存到数据库app设置的sftpShowHidden，保存成功后同步所有视图，失败保持原值并显示错误；旧设置缺失时默认false。

软链接通过 READLINK 获取原始目标、STAT 判断目标类型，每批最多并发 8 个；断链、权限不足或不支持时允许信息缺失，不阻断列表。目录链接可以直接进入，路径保持 `/bin` 等逻辑绝对路径，服务器负责跟随链接；仅相对输入以 REALPATH(".") 获取初始目录。逻辑折叠重复斜杠、`.`、`..`，不越过根目录。

当前仅支持安全的 UTF-8 单个名称；不支持任意字节名、控制字符或反斜线名，不以有损显示名称执行传输。

## 3. 上传

上传按钮通过原生选择器多选普通文件；操作系统拖入支持文件和目录。侧栏内任意落点均上传至**当前浏览目录**，先确认目标路径，再加入批次队列。拖出期间的原生 hover/drop 回流由 Rust 共享取消令牌和前端状态共同屏蔽。软件内 Drop 直接取消拖出并释放操作锁；上传必须先收到带真实路径的外部 Enter，随后仅消费一次 Drop，Leave 清除此状态。空路径或没有外部 Enter 的 Drop 直接忽略，即使晚于拖出结束也不签发上传授权或显示上传错误。

原生 drop 在 Rust 签发 owner-bound 一次性 dropId，前端仅接收引用及逻辑坐标，不提交任意本地路径。授权有效期 5 分钟，最多 16 批，每批最多 1000 个根路径；超限拒绝，未消费授权可按最旧项淘汰。macOS/GTK 原生坐标直接采用，Windows 按窗口 scale factor 转为逻辑坐标。

目录上传预扫描最多 64 层、10000 项，不跟随本地链接、不接受特殊文件。已有远端目录始终保留并合并；文件/目录类型冲突拒绝，不能通过移除目录解决冲突。已打开的目录链接可作为上传位置，上传树内部的同名链接不自动递归合并。

同名普通文件逐项原生确认，只有明确同意才覆盖。新文件独占创建；已有文件先打开并 FSTAT 核对普通文件，再 FSETSTAT 截断并分块写入。不使用远端临时文件或 hardlink。失败、取消或断网可能留下部分目标，旧内容不保证恢复；错误报告具体路径与完成计数。SFTPv3 缺少通用 NOFOLLOW/条件写入，存在并发替换路径竞态，不承诺原子覆盖。

## 4. 下载与原生拖出

下载按钮仅支持单个普通文件，通过原生保存对话框授权目标。文件写入目标同目录的独占临时项，权限为 0600，完成后以本地 hard_link 无覆盖发布；仅清理本任务的精确临时路径，清理失败报告路径，不覆盖已有目标。

macOS 可将最多 100 个普通文件/真实目录（可混选）拖到 Finder，采用 NSFilePromiseProvider 的 `public.data` / `public.folder`，无需先缓存完整内容。前端指针移动达到阈值后发起原生手势，IPC 命令统一校验最多 100 项；主线程启动前检查真实左键状态，已松开则按取消处理。

Finder 请求兑现目标后才显示任务和进度；无内容请求的 Esc/无效落点/应用内松开按取消收尾，不留下载记录。成功须 Copy 会话结束且全部承诺兑现成功。命令统一持有取消令牌，原生结束与独立松键检测共同收尾，内部落点不成为上传；外部松键后无写入回调时最多等待5秒接收剩余请求，正在写入的下载不受该空闲期限限制。

收尾拒绝迟到兑现，完成 WebView 必需的 mouseUp 补齐后才释放操作锁与前端忙碌状态；清理指针捕获/点击抑制，不激活窗口或抢 Finder 焦点。用户曾确认取消后首次点击及再次拖动恢复，当前完整原生矩阵仍待验收。

目录使用独立 OPENDIR 游标递归下载，不影响侧栏分页，最多 64 层/10000 项。不跟随源链接或特殊文件，只在 Finder 授权的新目标创建目录，不覆盖已有本地目录；失败保留已下载部分并报告路径及计数。链接拖出、Windows/Linux 原生拖出及按钮目录下载尚未实现。

## 5. 双栏文件工作区

左右栏从已保存主机选择，分别建立独立 SSH 连接并申请 SFTP 子系统；可选同一主机的两个独立连接。不借用终端会话，不创建 xterm、不申请 PTY/Shell；复用既有主机密钥核验、加密保险库凭据和多轮交互认证。文件专用 SessionManager 管理连接，最多两条；分页游标各自独立。切页保留连接与任务，断开/窗口退出关闭连接，重连不重放旧任务。通用跨功能共享租约仍未实现。

通过 Web Pointer Events 将勾选的普通文件/真实目录拖到另一栏，或点击“复制到另一侧”。目标固定为对侧当前浏览目录，不按文件夹行定位；不调用原生拖出、不设置文件 DataTransfer，不接受系统路径。Esc、无效落点、切页和窗口失焦仅取消手势，不创建任务。双栏当前不提供系统文件拖入/拖出入口，终端侧栏原生拖放保持独立。

`sftp_copy` 同时检查两个文件会话的 owner 与连接状态，获取双端操作锁和一个全局传输许可，Rust以64 KiB流式中转，不落盘、不将正文送入WebView。每批最多100根，源目录先完整扫描元数据，最多64层/10000项，不跟随源链接或特殊文件；已有目录只合并，目标树中链接拒绝自动合并；同名普通文件逐项确认后直接覆盖。取消或失败保留已完成内容，部分文件可能不完整，报告完成计数。

同一已知SSH连接标识（用户与主机名称）使用 REALPATH 检查目标，拒绝复制到自身及其子树；目录导航仍保留逻辑路径。不同主机别名指向同一服务器、远端硬链接和并发路径替换不能由SFTPv3通用接口证明对象身份；不承诺严格快照或原子覆盖。对拷期间两栏禁止切换连接和导航，展示当前路径、文件计数与字节进度，支持取消；完成/取消后刷新两端。窗口关闭确认包含双栏传输。

## 6. 任务与实现边界

- 文件正文仅在 Rust 流动，不进入 WebView、Pinia、数据库或日志；进度通过 Channel 节流约 150ms，u64 字节数使用十进制字符串。
- 64 KiB 数据块，全局最多 4 个传输，每浏览器同时一个操作。终端侧栏前端最多 32 个等待批次、保留 20 个结束记录；取消停止后续文件并释放句柄。
- `terminal-files` 定义目录元数据、只读列表端口、FileReader/FileWriter 与受界 copy_file；`terminal-sftp` 使用锁定的 russh-sftp RawSftpSession；`terminal-ssh::SshChannels` 提供 owner-bound 子系统。
- 无通用共享后台连接租约、持久化队列、断点续传、完整批量冲突策略或哈希校验。任务不跨重连恢复。

当前 IPC：

| 命令               | 用途                                                   |
| ------------------ | ------------------------------------------------------ |
| `sftp_connect`     | 从保存主机创建独立文件SSH连接，返回sessionId和控制事件 |
| `sftp_copy`        | 两个文件会话之间流式对拷，进度Channel                  |
| `sftp_list`        | 按 sessionId/path/more 分页列目录                      |
| `sftp_transfer`    | 原生选择器授权上传源或下载目标，传输进度 Channel       |
| `sftp_drop_upload` | 消费一次性 dropId，上传到当前目录                      |
| `sftp_start_drag`  | macOS 原生文件/目录承诺拖出                            |
| `sftp_cancel`      | 按 sessionId/transferId 取消                           |

命令均注册 AppManifest、handler 与 main capability，逐次检查窗口和会话所有权；远端路径权限以 SSH 账户可访问命名空间为界。普通 IPC 不接受任意本地路径。

## 7. 验证与资料

静态检查只能说明类型、格式和契约一致；用户已确认 macOS 取消后的交互恢复；双栏独立连接与对拷只有静态检查证据，未完成完整 Rust 编译、真实 SSH 或 Finder 运行验收。SP-10/11 覆盖目录分页与链接、上传合并/覆盖/取消、资源上限、断线隔离、三平台拖入、macOS 文件及目录拖出、无效落点与目标冲突；详见 [运行验收边界](01-product-requirements.md#11-运行验收边界)。

参考：[russh-sftp 3.0.1](https://docs.rs/russh-sftp/3.0.1/russh_sftp/)、[Tauri Webview](https://v2.tauri.app/reference/javascript/api/namespacewebview/)、[NSFilePromiseProvider](https://developer.apple.com/documentation/appkit/nsfilepromiseprovider)。原生拖放必须独立验收，Web DnD 可用不代表系统文件管理器已通过。

## 源码职责

固定双栏和侧栏均位于src/modules/files，workspace只负责固定Tab承载；types.ts保存端点/选择契约。fileEntries.ts共享目录优先排序、链接判定和名称展示；useSftpTransferQueue.ts管理侧栏任务，不持有DOM或监听原生拖放。分页代次、原生手势与双栏Pointer Events仍由各自视图维护。

壳内files/browser、upload、download复用浏览器获取及受界文件操作，commands保留owner校验、授权与调用编排；下载回调由 files 服务提供。terminal-sftp通过browser、remote_file和copy分离目录浏览、句柄读写与对拷，公开类型路径保持兼容，通用租约与持久任务仍未实现。

## 主机与路径表单校验

双栏主机选择、双栏路径及终端侧栏路径使用与控件共享的响应式 model，避免选择/输入同步校验时读取上一轮渲染的空值。保留 change/input/blur 及提交前验证，不修改连接、授权或传输契约。仅静态检查通过，首次选择保存主机、无效路径纠正及鼠标/键盘行为待运行复验。
